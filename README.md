# «В сборе» — сервис сбора команд для совместного спорта и досуга в мессенджере MAX

Проект разработан для **Хакатона MAX 2026** (трек **«Досуг и развлечения»**).

---

## 1. Назначение решения

«В сборе» — сервис внутри мессенджера MAX, помогающий людям быстро находить компанию для совместных спортивных и досуговых активностей (волейбол, футбол, пробежки, велопрогулки и др.) на ближайших площадках и в студенческих кампусах.

**Ключевая ценность**: Не просто каталог или доска объявлений, а инструмент гарантированного доведения встречи до минимального кворума участников. Сервис автоматически отслеживает набор игроков, подтверждает проведение встречи при наборе кворума и мгновенно оповещает лист ожидания, если кто-то отказался.

---

## 2. Основной пользовательский сценарий

1. **Создание встречи (Организатор)**:
   - Организатор задает параметры: тип активности (например, волейбол), локацию/кампус (площадка у корпуса №3), дату и время (сегодня в 19:00), уровень игры (любительский), лимит участников (6 человек) и минимальный кворум (4 человека).
2. **Поиск и запись (Участник)**:
   - Пользователь заходит в сервис, выбирает интересную активность и район/кампус.
   - Видит статус: «Собрано 3 из 6 мест (нужно еще 1 для подтверждения)».
   - Нажимает «Участвую».
3. **Автоматическое подтверждение встречи (Кворум достигнут)**:
   - Как только 4-й участник записался, сервис отправляет всем подтверждение («Встреча состоится! Собрано 4/6»).
4. **Управление отменой и лист ожидания**:
   - Если один из участников отменяет запись, статус обновляется.
   - Пользователи из листа ожидания (или подписанные на волейбол в этом кампусе) мгновенно получают приглашение занять освободившееся место в один клик.

---

## 3. Состав и архитектура решения

- **MAX Bot Service**: сервис взаимодействия с пользователем через API платформы MAX (`https://platform-api2.max.ru`), клавиатуры и инлайн-кнопки.
- **Backend / Core Engine**: бизнес-логика сбора кворума, управления статусами встреч, листа ожидания и алгоритма оповещений.
- **Database**: персистентное хранилище (пользователи, встречи, подписки, логи активности).

*(Детальная архитектурная диаграмма и модель данных будут размещены в `docs/architecture.md`)*

## 4. Быстрый запуск всех компонентов через Docker

Запуск всех компонентов решения выполняется **одной командой**:

```bash
docker compose up -d --build
```

## 5. Параметры и переменные окружения

Перед запуском скопируйте `.env.example` в `.env` и укажите необходимые значения:

```bash
cp .env.example .env
```

| Переменная | Описание | Значение по умолчанию / Пример |
|---|---|---|
| `MAX_BOT_TOKEN` | Токен чат-бота MAX | Выдается организаторами хакатона |
| `MAX_API_BASE_URL` | Базовый URL API MAX | `https://platform-api2.max.ru` |
| `BOT_MODE` | Режим работы (`polling` / `webhook`) | `polling` |
| `DATABASE_URL` | Строка подключения к БД | `sqlite+aiosqlite:///./data/vsbore.db` |
| `SERVER_PORT` | Порт приложения / вебхука | `8000` |
| `LOG_LEVEL` | Уровень логирования | `INFO` |

> ⚠️ **Важно**: файл `.env` с реальными токенами находится в `.gitignore` и никогда не попадает в git-репозиторий.

## 9. Описание работы с данными и порядок работы с тестовыми данными

При первом старте сервиса автоматически инициализируются начальные тестовые данные (seed-данные):
- Демо-площадки кампуса и виды активности (волейбол, футбол, велопрогулка, бег).
- Несколько запланированных встреч с разной степенью наполненности (для быстрой демонстрации сценария «добора кворума»).

Команда для принудительного сброса/перезаполнения тестовых данных будет описана в процессе реализации.

## 10. Пошаговый сценарий проверки для жюри

1. Открыть чат-бота в MAX (ссылка и username будут указаны на первом слайде презентации).
2. Отправить команду `/start` или нажать кнопку начала.
3. Пройти выбор интересов (например, указать «Волейбол», уровень «Любитель»).
4. Нажать «Найти активности» → выбрать предложенную встречу на кампусе.
5. Нажать «Записаться» → убедиться, что счетчик участников обновился и бот прислал подтверждение статуса.
6. Проверить сценарий создания встречи: нажать «Создать встречу», указать время, площадку и лимиты.
7. Проверить сценарий отмены участия.

## 11. Примеры ожидаемого поведения системы

- **При наборе кворума**: всем участникам встречи приходит push-сообщение в MAX: «Ура! Минимальный состав собран (4/6). Встреча состоится в 19:00 на площадке №3».
- **При переполнении**: кнопка записи меняется на «Встать в лист ожидания». При отказе кого-то из основного состава первый в очереди получает уведомление с таймером на подтверждение.
- **При некорректном вводе**: бот вежливо подсказывает правильный формат и возвращает на предыдущий шаг без падения состояния.

---

## 12. Известные ограничения MVP

- Геолокация на этапе MVP работает по выбору района/кампуса или списку площадок (без трекинга точного домашнего адреса пользователя из соображений приватности).
- Бронирование и оплата аренды коммерческих площадок вынесены за рамки первой версии (Won't Have для хакатона).
- Расписание встреч формируется организаторами сообществ и пользователями (модельные данные площадок).
