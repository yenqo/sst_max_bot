# «В сборе»

Чат-бот в MAX для сбора людей на любительский спорт и досуг в студенческом кампусе.
Хакатон MAX 2026, трек «Досуг и развлечения».

Бот в MAX: `@t760_hakaton_max_bot`

## 1. Назначение

Собрать компанию на волейбол или пробежку обычно пытаются в общих чатах: сообщение тонет, непонятно, сколько человек придёт, и встреча часто срывается. «В сборе» решает это так:

- у встречи есть минимальный состав (кворум) и лимит мест;
- когда записывается нужное число людей, встреча подтверждается и всем участникам приходит уведомление;
- если мест нет, человек встаёт в лист ожидания; при отказе участника первый из листа автоматически занимает место.

Пилотный кампус — МГУ (Воробьёвы горы).

## 2. Основной пользовательский сценарий

1. Участник открывает «Найти активности» и видит ближайшие встречи: вид спорта, время, заполненность («3/6»).
2. В карточке встречи — место, время, уровень и сколько человек не хватает до подтверждения. Кнопка «Метка на карте» присылает геолокацию площадки.
3. Участник нажимает «Записаться». Если этим набран кворум, встреча подтверждается, остальные участники получают уведомление.
4. Если мест нет — «Встать в лист ожидания». Когда кто-то отменяет запись, первый в листе переводится в основной состав и получает сообщение.
5. Организатор создаёт встречу: активность, площадка, день, время, состав, уровень, комментарий. Сам он становится первым участником.

## 3. Состав и архитектура

Один сервис на Python 3.11 (FastAPI, SQLAlchemy async, httpx), БД — SQLite в примонтированном каталоге `./data`.

```
MAX Bot API ⇄ api/max_client.py → bot/handlers.py → services/meeting_service.py → SQLite
               (long polling)      bot/create_flow.py  services/catalog.py
                                                        services/demo_data.py
```

| Модуль | Что делает |
|---|---|
| `app/api/max_client.py` | Запросы к MAX API: сообщения, кнопки, геолокация, получение событий |
| `app/bot/handlers.py` | Обработка событий MAX: меню, списки, карточки, запись и отмена |
| `app/bot/create_flow.py` | Пошаговое создание встречи |
| `app/services/meeting_service.py` | Логика записи, кворума и листа ожидания |
| `app/services/catalog.py` | Справочник кампуса: виды активности, площадки с координатами |
| `app/services/demo_data.py` | Тестовые встречи |
| `app/api/endpoints.py` | `GET /health`, `POST /webhook` |

Таблицы: `users`, `meetings`, `meeting_participants` (статус `joined` / `waitlist` / `cancelled`), `meeting_drafts` (незавершённый текстовый ввод при создании встречи).

## 4. Запуск

```bash
cp .env.example .env   # указать MAX_BOT_TOKEN
docker compose up -d --build
```

Проверка: `curl http://localhost:8000/health` → `{"status":"alive"}`, в `docker logs vsbore_bot` — строка `Bot authorized as @...`.

## 5. Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `MAX_BOT_TOKEN` | Токен бота MAX. Обязательна | — |
| `MAX_API_BASE_URL` | Адрес MAX API | `https://platform-api2.max.ru` |
| `BOT_MODE` | `polling` или `webhook` | `polling` |
| `DATABASE_URL` | Строка подключения к БД | `sqlite+aiosqlite:///./data/vsbore.db` (в Docker — `/app/data/vsbore.db`) |
| `TIMEZONE` | Часовой пояс времени встреч | `Europe/Moscow` |
| `LOG_LEVEL` | Уровень логов | `INFO` |

## 6. Порты

`8000` — HTTP-сервер приложения (`/health`, `/webhook`). В режиме polling снаружи он не нужен.

## 7. Зависимости

Версии зафиксированы в `requirements.txt`. Образ — `python:3.11-slim`.

## 8. Внешние сервисы и интеграции

- **MAX Bot API** — единственный внешний сервис, в Docker не воспроизводится. Нужен токен бота. Сертификат `platform-api2.max.ru` выпущен Russian Trusted Root CA (Минцифры), которого нет в стандартном наборе `certifi`; корневой сертификат лежит в `app/certs/` и подключается только к HTTP-клиенту бота.
- **Режим webhook** требует публичного HTTPS-адреса и ручной регистрации подписки (`POST /subscriptions` в MAX API). Бот её не регистрирует, по умолчанию используется long polling.
- **Собственного API у решения нет.** `/webhook` и `/health` — служебные, поэтому `DATA-API.yaml` не прилагается.

Модельные данные (FAQ, п. 13):

- Справочник площадок — статический список из 7 мест кампуса МГУ, координаты взяты из OpenStreetMap. Для тиражирования нужен импорт площадок из OpenStreetMap / 2ГИС или от вуза.
- Демо-встречи и их участники (`demo_1` … `demo_9`) синтетические, им бот сообщения не отправляет.

## 9. Работа с данными

Хранится только необходимое для записи на встречи: ID пользователя MAX и имя, встречи, записи. Геолокацию пользователя бот не запрашивает — на карте показывается только площадка. Время хранится в часовом поясе `TIMEZONE`. Новые колонки добавляются при старте (`ADDED_COLUMNS` в `app/database/session.py`).

## 10. Тестовые данные

Создаются автоматически при старте и раз в час: если у демо-встречи нет предстоящего повтора, создаётся новый на ближайший день. Поэтому список не пустеет, сколько бы ни длилась проверка.

| Встреча | Начало | Состав | Что показывает |
|---|---|---|---|
| Волейбол у спорткомплекса МГУ | 19:00 | 3/6, кворум 4 | одна запись — и встреча подтверждается |
| Футбол 5×5 на стадионе МГУ | 20:00 | 9/10, кворум 8 | подтверждена, одно место |
| Настольный теннис в спорткорпусе | 18:30 | 4/4 + 1 в листе | лист ожидания |
| Велопрогулка по набережной | 11:00 | 1/8, кворум 3 | начало сбора |
| Утренняя пробежка по Воробьёвым горам | 07:30 | 2/∞, кворум 2 | без ограничения мест |

Сброс к исходному состоянию (удаляет все встречи и записи, пользователи остаются):

```bash
docker compose exec app python -m app.services.demo_data --reset
```

## 11. Сценарий проверки

1. Открыть `@t760_hakaton_max_bot` в MAX, нажать «Начать» или отправить `/start`.
2. «Найти активности» → «Волейбол · 19:00 · 3/6» → «Записаться». Карточка обновится: «Ура! Вы записаны, и минимальный состав собран (4/6)», статус «Встреча подтверждена».
3. «Метка на карте» — придёт геолокация площадки.
4. «К списку активностей» → «Настольный теннис · 4/4» → «Встать в лист ожидания».
5. «Главное меню» → «Мои встречи» → волейбол → «Отменить участие». Счётчик вернётся к 3/6, подтверждение снимется.
6. «Создать встречу» → пройти шаги. На шаге времени можно написать «19:40», на шаге состава — «5-12» или «5+», комментарий — любой текст до 50 символов. «Опубликовать» — встреча появится в списке со звёздочкой.
7. Вернуть данные в исходное состояние — команда из раздела 10.

Если запускаете свою копию в Docker, используйте отдельный токен: два экземпляра с одним токеном делят входящие события, и бот будет отвечать через раз.

## 12. Ожидаемое поведение

- Нажатие кнопки меняет текущее сообщение; новые сообщения приходят на `/start`, на введённый текст и в виде уведомлений другим участникам.
- Больше 10 встреч — список сначала группируется по видам активности, внутри — страницы по 10.
- Некорректный ввод («25:00», «1» участник, комментарий длиннее 50 символов) — бот объясняет ошибку и остаётся на том же шаге.
- Кнопка из старого сообщения на удалённую встречу — «Эта встреча больше не существует» с возвратом к списку.
- Произвольный текст вне создания встречи — подсказка и главное меню.

## 13. Известные ограничения

- Один пилотный кампус, площадки только из справочника.
- Нельзя отменить или изменить встречу целиком — только своё участие.
- Нет напоминаний перед началом и подписок на виды активности.
- Нет бронирования и оплаты площадок.
- SQLite рассчитана на одну копию бота; для нескольких нужна PostgreSQL.
- Режим webhook требует ручной регистрации подписки (раздел 8).

## 14. Остановка и перезапуск

```bash
docker compose down             # остановить
docker compose up -d --build    # запустить снова
```

База лежит в `./data` на хосте и сохраняется между перезапусками. Чтобы начать с чистой базы, остановите сервис и удалите `./data/vsbore.db`.
